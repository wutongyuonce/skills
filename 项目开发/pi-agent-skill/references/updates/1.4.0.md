# 1.2.0 → 1.4.0 发布区间核对

目标查询：2026-10-27，npm `dist-tags.latest` = `1.4.0`（`legacy-node20` 仍为 `0.74.2`）。旧基线 `1.2.0`。材料来自 `npm pack` 取得的两个发布 tarball：`@earendil-works/pi-coding-agent@1.2.0`、`@1.4.0`，并用 `@earendil-works/pi-ai@1.2.0`、`@1.4.0` 对照跨包类型。元数据未提供 `gitHead`，本报告不推测对应提交。

完整变更区间为 **1.3.0（2026-10-15）与 1.4.0（2026-10-21）** 两个发布条目；1.2.0 是旧基线，其条目不在本次区间内。两版本都没有标记 Breaking Changes，但存在行为变化（见下表）。

- coding-agent 1.4.0 tarball：`earendil-works-pi-coding-agent-1.4.0.tgz`，sha1 `7f5dd2a4f7fa46ed252465ac4d341831896b1fc2`，integrity `sha512-Z41LpZ3yYHSC/UUps6Mr39UMFPwH8elhJBG9DY1P7kuzsE5qSK/6eMj2EHzO5evJRQWLbKSqUMw+4nCNtIyiQg==`。`engines.node` 仍为 `>=22.19.0`。
- 依赖变化：1.2.0 对 `pi-ai` / `pi-agent-core` / `pi-codemode` / `pi-mcp` / `pi-tui` 使用 `^1.2.0`；1.3.0 起改为**精确版本**（1.4.0 为 `1.4.0`），用于阻止 fresh install 混合不同发行版的内部包。
- 包根公开导出：无删除，仅新增 `formatReadLineRange`。`exports` 仍为 `.` 与 `./rpc-entry`。

## 冲突与取舍

- **classifier `compat` 的可写路径**：`docs/models.md` 写“Extension classifier models accept `compat` too”，但 `core/extensions/types.d.ts` 的 `ProviderClassifierModelConfig` 没有 `compat` 字段；带 `compat` 的是 `core/provider-composer.d.ts` 的类型，且未从包根导出。因此文档只声明 `models.json` provider 级 `compat` 与公开的 `ClassifierModel.compat`，不宣称扩展 `registerProvider` 的 classifier 配置可写该字段。
- **`parseModelPattern` 移除**：该函数从未从包根导出（只在 `core/*` 内部），不属于公开 API；skill 未引用，无需迁移说明。`ResolveCliModelResult` 未变；`resolveCliModel` 的输入仅新增可选 `inlineApiKey`，`resolveModelScope*` 的公开返回未变。
- **`ProviderRequestOptions.telemetryContext` → `telemetry`**：pi-ai 公开类型改名，但 skill 未记录该字段，本次不新增；实现自定义 stream 且用到遥测的高级用户需按目标 `.d.ts` 调整。
- **`ToolCall.argumentsError`**：新增字段用于非对象 JSON 参数；skill 未承诺旧行为，未新增说明。
- **1.3.0 模型选择歧义**（`--model` 优先有凭据的 provider、`--models` 为每个 provider 添加并告警）属 CLI 解析路径，skill 未记录 `resolveCliModel` 的细节，本次不纳入 SDK 文档。

## 实际验证

环境：Node 22.22.2、TypeScript 5.9.3；验证项目锁定 coding-agent / pi-ai / pi-agent-core / pi-codemode / pi-mcp / pi-tui / pi-telemetry 均为 1.4.0，`typebox` 1.3.27、`diff` 8.0.4，`@modelcontextprotocol/sdk` 1.32.1（补 Google GenAI 的 optional peer 声明解析）。锁文件无临时路径。

1. `npm run check:types`（strict、Bundler/ESNext、无 skipLibCheck）：通过。
2. `node --experimental-strip-types check-sdk.ts`：全部断言通过，网络尝试 0，临时 cwd/agentDir/会话在 finally 清理。新增断言覆盖：
   - `generateSummary` 的第三参不再产生请求级 `maxTokens`（传 16384 与 0 均为 `undefined`）；
   - 跨模型 thinking 块被丢弃、同模型保留（`transformMessages`）；
   - `sessionShareDestination` 默认 `auto`，setter/getter 可用；
   - `formatReadLineRange(10, 5) === ":10-14"`；
   - 恢复会话以 transcript loadout 为基准应用 `+check_inactive` / `-bash`。
3. `node check-examples.mjs ..`：161 个完整块/hook 编译通过，0 diagnostics；另记 256 reference fragments、5 signature/pseudocode、5 intentional negatives。签名、伪代码与故意错误示例不冒称独立编译通过。
4. `python3 validation/check-docs.py`：71 个 Markdown、978 个本地文件链接、79 个文内锚点，active 安装 pin 全为 1.4.0。
5. 本次同时修复了 19 个 1.2.0 时期遗留的失效锚点（如 `#坑-4…`、`#工具选择规则…`、`#模式-5…`），并把锚点校验纳入 `check-docs.py`。
6. 严格 NodeNext 复跑：仍为 42 个 `pi-ai/dist/providers/*.models.d.ts` 的 TS1543（JSON import 缺 `type: "json"`），与 1.2.0 相同。未使用 skipLibCheck、ts-ignore 或声明补丁；不声称 NodeNext 通过。
