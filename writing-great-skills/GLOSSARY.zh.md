# 术语表：构建优秀 Skill

这是关于什么让一个 skill 变好的领域模型。skill 的存在，是为了从随机系统中拧出确定性；根本德性是 **可预测性**，下面每个术语都是作用于它的杠杆。这是 [`writing-great-skills`](SKILL.zh.md) 的披露型参考资料。

术语按轴线分组：**调用**（skill 如何被触达）、**信息层级**（内容如何组织）、**引导**（agent 的运行时行为如何成形）和 **修剪**（如何保持精瘦）。每个 **失效模式** 都放在能治它的杠杆旁边，并标记为_失效模式_。

任何定义中的**加粗术语**都在本术语表中有定义；可通过标题找到。

## 可预测性

skill 让 agent 在每次运行中以相同_方式_行动的程度，也就是相同过程，而不是相同输出（一个头脑风暴 skill 应该_可预测地_发散；它的 token 会变化，但行为不会）。这是其他所有术语服务的根本德性；成本和可维护性是它的症状，不是它的竞争者。

_避免使用_：一致性、可靠性、鲁棒性、输出确定性

## 调用

skill 如何被触达，以及这个选择带来的两种负载。

### 模型调用型

保留 **description** 字段的 skill，因此 agent 可以看见它并自主触发它；人类仍然可以输入它的名字，所以模型调用总是_包含_用户触达。不存在“仅模型可用”的状态：description 只会_增加_ agent 发现能力，永远不会移除人类触达。它用每一轮永久性的 **上下文负载** 换取可发现性。它也能被其他 skill 触达，因为让它可被 agent 发现的 description 也让它可被调用。内容全是 **参考资料** 的模型调用型 skill，也可以作为共享参考资料的一个归宿：另一个 skill 可以调用它，所以多个 skill 都需要的参考资料可以住在一个地方。只有当 agent 必须自己触达这个 skill 时才选择模型调用；如果它永远只会被手动触发，就去掉 description，不付上下文负载。

_避免使用_：能力、工具、功能

### 用户调用型

去掉 **description** 的 skill：agent 看不见它，只有人类输入其名字时才能触达它（用户_专属_；而 **模型调用型** 是用户_和 agent_ 都可触达）。它用 agent 可发现性换取零 **上下文负载**。因为没有 description，除了人类以外，任何东西都不能触达它：没有其他 skill 能触发它。

_避免使用_：流程、工作流、命令

### Description

skill 的机器可读触发器，也是 **模型调用型** skill 被迫始终加载的那个 **上下文指针**。它的存在本身就是调用轴：保留它，skill 就是模型调用型（并可被其他 skill 触达）；删除它，skill 就是 **用户调用型**，只能由人类触达。它是模型调用型 skill 的 **上下文负载** 来源。

_避免使用_：frontmatter、摘要

### 上下文指针

agent 上下文中持有的一段引用，它命名某些上下文外材料，并编码触达它的条件。**description** 是顶层上下文指针（上下文窗口 -> skill）；指向披露文件的指针是在下一层的同一种东西。决定 agent _何时_触达以及_多可靠地_触达的，是它的措辞，而不是目标。必需材料后面如果只有一个措辞很弱的指针，那是方差 bug：先修指针措辞，只有锐化失败时才把材料拉回内联。

_避免使用_：链接、引用、导入

### 上下文负载

**模型调用型** skill 强加给 agent 上下文窗口的成本：它的 **description** 总是被加载，消耗 token 和注意力。**用户调用型** skill 因没有 description 而逃开这个成本；它也是拆出更多模型调用型 skill 的刹车。

_避免使用_：token 成本、上下文膨胀

### 认知负载

**用户调用型** skill 强加给人类的成本：他们必须在脑中记住哪些 skill 存在、何时该用哪一个（人类就是索引）。**模型调用** 因可被 agent 发现而移除这个成本；它也是拆出更多用户调用型 skill 的刹车。它不是一个需要最小化的成本：它是人类能动性的价格，也是某些 skill 保持用户调用型的原因。把它花在人类判断重要的地方；在不重要的地方移除它。

_避免使用_：人类索引、负担、开销

### 路由 Skill

一种 **用户调用型** skill，职责是指向你的其他用户调用型 skill：列出每一个，并说明什么时候该用它，这样人类只需要记住一个 skill，而不是很多个。它只能提示，不能触发它们：用户调用型 skill 没有 **description**，所以除了人类以外什么都触达不了它们。当用户调用型 skill 变多时，它是 **认知负载** 的解法。

_避免使用_：分发器、菜单、注册表、索引、路由流程

### 粒度

你把 skill 划分得多细。划分越细，就越会消耗两种负载之一：更多 **模型调用型** skill 消耗 **上下文负载**（更多 description 挤进窗口并争夺注意力）；更多 **用户调用型** skill 消耗 **认知负载**（人类要记住并伸手去拿的东西更多）。两种切法引导划分。按 **调用** 切分：当你有一个独立 **主导词** 可以触发它，也就是你确实会在 prompts 中使用的触发词时，拆出一个模型调用型 skill。按 **序列** 切分：当某个步骤的 **完成后步骤** 需要被隐藏时，拆开一串 **步骤**，因为把它隔离在自己的上下文中会清空后续内容。也要警惕反面：合并序列会把每个步骤的完成后步骤暴露给前面的内容，诱发过早完成。

_避免使用_：分块、模块化

## 信息层级

skill 的内容如何安排，以及每一块内容在梯子上放多深。

### 信息层级

skill 的内容按 agent 对它的即时需求程度排序，是由两个切分产生的一把梯子：在文件内还是在指针后面，步骤还是参考资料。梯级如下：

- **步骤**：文件内，最高层级
- **参考资料**：文件内，次级
- **参考资料**：披露型，在 **上下文指针** 后面

没有 **步骤** 的 skill 只使用底下两个梯级，常常是合法的扁平同级集合（比如评审的每条规则都在同一层级），这种安排很好，不是异味。层级独立于调用：无论 skill 全是步骤、全是参考资料，还是二者兼有，它都可以是模型调用型或用户调用型。当一个 skill 有步骤时，本应披露的文件内参考资料会埋住步骤，并让注意力是否落在步骤上变成掷硬币，这是方差杠杆，不只是可读性问题。保持梯子顶部清晰；能下推的都往下推。

_避免使用_：结构、组织、布局

### 步骤

agent 执行的有序动作。当 skill 有步骤时，这是内容的最高层级，也是值得放进 SKILL.md 的部分。不是每个 skill 都有步骤：一个 skill 可以全是步骤（`tdd`）、全是 **参考资料**（一次评审），或二者兼有，并且这与调用方式无关。每个步骤都以一个 **完成标准** 结束，清晰或含糊。

_避免使用_：工作流、指令、编排

### 参考资料

agent 按需查阅的材料：定义、事实、参数、示例、条件性指令。当 skill 有 **步骤** 时，它次于步骤；当 skill 没有步骤时，它就是全部内容；它也可以完全存在于任何 skill 之外，参见 **外部参考资料**。它通过 **上下文指针** 触达，也是 **渐进披露** 的首要候选。

_避免使用_：辅助材料、文档、背景

### 外部参考资料

存在于 skill 系统之外的 **参考资料**：一个普通文件，没有 **description**，没有 **步骤**，不可调用，但任何 skill 都能指向它。它是不需要自行触发的共享参考资料的归宿，也是两个 **用户调用型** skill 能使用的唯一共享归宿，因为二者都没有 description，所以谁也不能触发谁。

_避免使用_：文档、资源、知识库

### 渐进披露

把 **参考资料** 沿梯子下移：从 SKILL.md 移出，放到 **上下文指针** 后面，让顶部保持清晰。它主要不是 token 优化；它是保护 **信息层级** 的方式。它由 **分支** 授权：只被部分分支需要的内容可以披露，每条路径都需要的内容应当内联；如果一个指针在必需材料上触发不可靠，就锐化它的措辞，只有这仍失败时才拉回内联。

_避免使用_：懒加载、分块

### 共址

把 agent 需要同时使用的材料放在一个地方：一个概念的定义、规则和注意事项放在单个标题下，而不是散落在文件各处。这样读到一部分时，它的邻近内容也会随之进入视野。它是 **信息层级** 在文件内的同伴：层级排列一块内容_放多深_；共址决定它到了那里后_和什么放在一起_。一组 **参考资料** 的正文没有固定正确格式；测试标准是 skill 应该读起来像为 agent 写的文档，而分组材料比散落材料更像文档。它不同于 **重复**：重复是在两个地方复述同一含义，散落则是把一个含义拆碎到许多地方。

_避免使用_：分组、聚类、内聚

### 蔓延

_失效模式。_ 一个 skill 只是太长，也就是 SKILL.md 中行数太多；这与内容是否陈旧或重复无关。即使所有内容都鲜活且唯一，一个 skill 也可能蔓延。它的成本包括可读性（agent 在行动前要跋涉过更多内容，注意力在多余内容间变薄）、可维护性（每多一行，就多一行需要保持 **相关**）和 token。解法是 **信息层级**：把 **参考资料** 下推到 **上下文指针** 后面，并按 **分支** 或序列拆分，让每条路径只携带需要的东西。它不同于 **沉积**（陈旧积累带来的长度）和 **重复**（重复含义带来的长度）：蔓延就是长度本身，无论成因为何。

_避免使用_：臃肿、长度、大小、啰嗦

## 引导

把 agent 运行时行为塑造成 **可预测性** 的杠杆。

### 分支

skill 被调用的一种不同方式，也就是 skill 处理的一个案例，因此不同运行会沿着它走不同路径。步骤很多的 skill 可能携带许多分支；线性 skill 没有分支。

_避免使用_：路径、案例、分叉

### 主导词

一个紧凑概念，也称为 _Leitwort_，已经存在于模型预训练中，agent 在运行 skill 时会用它思考。它通过调用模型已有先验，用尽可能少的 token 编码行为原则（例如 _lesson_、_proximal zone of development_、_fog of war_、_tracer bullets_）。它作为 token 反复出现，而不是作为句子反复出现，于是在 skill 中积累分布式定义，并锚定一整片行为区域。自造词也可以，如果你定义清楚；但造出来的词不会招募先验，你要用定义 token 来支付预训练词免费提供的东西。优先伸手去拿已有词。

主导词以两种方式服务于 **可预测性**。在正文中，它锚定 **执行**：每次这个概念出现，agent 都会伸手去拿同一种行为；在扁平参考资料中，它会把注意力聚焦到某类需要寻找的东西上，每次运行都招募正确的检查。在 **description** 中，它锚定 **调用**；而且不只在 skill 内部：当同一个词存在于你的 prompts、你的 docs 和你的 codebase 中时，agent 会把这种共享语言连接到 skill，并更可靠地触发它。用你真正希望调用 skill 时会使用的主导词来措辞 description。

_避免使用_：关键词、术语、母题

### 完成标准

告诉 agent 一个工作单元已经完成的条件，也就是它用来判断的目标。两个性质让它成为杠杆，而不只是品质。它的 **清晰度**（agent 能否判断完成与未完成？）抵抗 **过早完成**：含糊边界（“理解已经达成”）会让 agent 宣告完成并滑向下一步；这个轴需要_步骤_才能起作用，因为过早完成是步骤之间的失效。它的 **要求强度**（要求多少工作）设定 **幕后工夫**：“每个修改过的模型都已说明”会迫使工作更彻底，而“产出一个变更列表”不会；这个轴_不_受步骤限制：它也能约束一组扁平参考资料，这就是没有步骤的 skill 仍能携带穷尽性门槛（“每条规则都已应用”）的方式。最强的标准既可检查又穷尽。

_避免使用_：完成条件、退出条件、停止规则

### 幕后工夫

agent 在单个步骤内部于幕后做的工作：读文件、探索代码库、修改、挖出所需材料，而不是把任务推回给用户。它位于步骤结构之下：绝不作为自己的独立步骤写出来，而是潜伏在措辞中，由 agent 而不是 skill 控制。它是 **完成后步骤** 跨步骤拉力在步骤内的对应物。它由 **主导词**（_comprehensive_、_thorough_）或要求工作穷尽的 **完成标准** 抬高，包括应用于扁平参考资料的要求轴，这会推动由扁平参考资料构成的 skill 覆盖其全部梯级。当要求缺失，或 **过早完成** 截断步骤时，它会变薄。

_避免使用_：范围、努力、勤勉、覆盖

### 完成后步骤

当前步骤之后的 **步骤**。当它们可见时，会把 agent 向前拉进 **过早完成**；它看见得越多，拉力越强。防御方式是通过拆分步骤序列来隐藏它们。

_避免使用_：视界、战争迷雾、前瞻

### 过早完成

_失效模式。_ 在当前步骤真正完成之前就结束，因为 agent 的注意力滑向“已经完成”，而不是滑向工作本身。这是步骤之间的失效：它需要 **步骤** 才会发生；没有步骤的 skill 如果过早退出，那不是过早完成，而是在未满足要求下 **幕后工夫** 变薄。它是两股力量之间的拉扯：可见的 **完成后步骤**（向前的拉力）和 **完成标准** 的清晰度（阻力；锋利、可检查的门槛能守住，含糊的门槛会让步）。含糊是必要条件：锋利边界能抵抗拉力，无论后面可见多少步骤，所以一个从不匆忙的步骤不需要防御。对于确实会匆忙的步骤，有两个杠杆，但使用顺序很重要：**先锐化边界**，因为它本地且便宜。只有当标准不可避免地含糊，且你真的观察到匆忙时，才 **隐藏后续步骤**；而隐藏只有跨过真实上下文边界才有效（用户调用型交接或 subagent 派发；内联的模型调用不会清空上下文中的后续步骤）。它是幕后工夫变薄的一个原因，但二者不同：即使一个步骤完整运行到底，幕后工夫仍可能很薄。

_避免使用_：过早收束、匆忙、走捷径

### 否定

_失效模式。_ 用禁止来引导，也就是告诉 agent _不要_做什么，会把被禁止的行为拖进上下文，让它变得_更_容易出现，而不是更少出现。_Don't think of an elephant_，然后满脑子都是那头大象；_never write verbose comments_，而冗长正是 agent 刚刚读到的模式。否定是一个弱修饰词，会被强激活的概念碾过，所以禁令会半读成一条去做那件事的指令。它的 **主导词** 就是那头“大象”：任何禁止语句点名带进框架的东西。解法：提示 **正向目标**，描述目标行为（“write one-line comments”），让被禁止的行为根本不被说出口。只有当某个行为无法正向表述而必须设硬护栏时，禁止才值得占位；即便如此，也要配上正向目标，让注意力落在应该做什么上。

_避免使用_：反讽反弹、don't-prompting、粉红大象

## 修剪

让 skill 保持精瘦：每个补救手段都配对一个它所治疗的失效。

### 单一事实来源

期望状态：每个含义都只存在于一个权威位置，因此改变 skill 行为只需改一处。**重复** 是对它的违反。

_避免使用_：归宿、规范位置

### 重复

_失效模式。_ 同一个含义有不止一个 **单一事实来源**。它增加维护成本（改一处，就必须改其他处）、token 成本，并膨胀显著性：重复一个含义，会让它在梯子上的权重超过真实层级。它是 **主导词** 的意外反面；主导词通过重复 token 来有意提高注意力，而不是重复含义。

_避免使用_：复述、冗余

### 相关性

一行是否仍然影响 skill 要做的事，也就是决定保留什么的镜头。一行失去相关性，可能是因为它从未影响任务（只是阐释，或者某个 **分支** 本该披露出去），也可能是因为它变旧：随着它描述的行为或世界变化而过时。更短的 skill 更容易保持相关，因为每一行检查起来更便宜。它不同于 **空操作**：相关性问的是一行是否影响任务，而不是它是否改变行为。

_避免使用_：承重、陈旧性、新鲜度

### 沉积

_失效模式。_ 旧内容层层沉入 skill 且从不清理，因为添加让人觉得安全，删除让人觉得冒险；于是陈旧且不相关的行积累起来，你必须向下钻取才能找到仍然鲜活的内容。任何没有修剪纪律的 skill 默认都会如此；它是 **相关性** 的缓慢侵蚀，不同于 **重复** 的含义复述。

_避免使用_：堆积、臃肿、垃圾、腐坏

### 空操作

_失效模式。_ 一条不改变任何东西的指令，因为模型默认就已经会这样做：你付出负载，却只是告诉 agent 去做它本来就会做的事。测试是：这一行相较默认行为是否改变了行为？一行可以完全 **相关**，但仍然是空操作。让 **主导词** 免费的同一批先验，也让空操作变得无价值。

主导词是一种_技巧_；空操作是对一行的_判决_，二者会交叉。一个主导词如果弱到无法超过默认行为，就是空操作（比如 agent 已经算是会彻底时还写 _be thorough_）；修复方式是换一个能通过判决的更强词（_relentless_），而不是换一种技巧。所以空操作测试“它相较默认行为是否改变了行为？”也就是评估主导词的重复是否值得的方式。这是相对于模型的，不是相对于读者的：两个人争论一行是不是空操作，其实是在争论默认行为是什么；解决方式是运行这个 skill，而不是辩论。

_避免使用_：冗余指令、重述显而易见之事、啰嗦强调
