skill 的存在，是为了从随机系统中拧出确定性。**可预测性**，也就是 agent 每次运行都采取相同的_过程_，而不是产出相同的输出，是根本德性；下面的每个杠杆都服务于它。

**加粗术语**在 [`GLOSSARY.zh.md`](GLOSSARY.zh.md) 中有定义；完整含义请去那里查阅。

## 调用

有两种选择，各自付出不同成本：

- **模型调用型** skill 保留 **description**，因此 agent 可以自主触发它，其他 skill 也可以触达它（你仍然也可以直接输入它的名字）。它会贡献 **上下文负载**，因为 description 每一轮都会待在上下文窗口里。机制：省略 `disable-model-invocation`，并写一个面向模型的 description，包含丰富的触发措辞（“Use when the user wants…，mentions…”）。
- **用户调用型** skill 会把 description 从 agent 的可见范围中剥离：只有你输入它的名字时才能调用它，其他 skill 也不能调用它。它没有上下文负载，但会消耗 **认知负载**：_你_就是那个必须记住它存在的索引。机制：设置 `disable-model-invocation: true`；`description` 变成人类可读的一行摘要，去掉触发列表。

只有当 agent 必须自己触达这个 skill，或者另一个 skill 必须触达它时，才选择模型调用。如果它只会被手动触发，就把它做成用户调用型，不付上下文负载。

当用户调用型 skill 多到你记不住时，堆起来的认知负载可以用一个 **路由 skill** 解决：一个用户调用型 skill，列出其他 skill，并说明什么时候该用哪一个。

## 编写 description

模型调用型 **description** 做两件事：说明这个 skill 是什么，并列出应当触发它的 **分支**。每个词都会增加 **上下文负载**，所以 description 比正文更需要狠修剪：

- **把 skill 的主导词前置**：description 正是在这里完成它的调用工作。
- **每个分支只保留一个触发条件。** 只是给同一分支改名的同义说法属于 **重复**：“build features using TDD … asks for test-first development” 是同一个分支写了两遍。合并它们，只保留真正不同的分支。
- **删掉正文里已经有的身份说明。** description 只保留触发条件，以及任何“当另一个 skill 需要……”的触达从句。

## 信息层级

skill 由两类内容构成：**步骤**和**参考资料**。两者可以自由混合：一个 skill 可以全是步骤，全是参考资料，或二者兼有。核心决策是使用哪一类，以及每一类放在 **信息层级** 的什么位置。信息层级是一把梯子，按 agent 对材料的即时需求程度排序：

1. **skill 内步骤**：`SKILL.md` 中有顺序的动作，最高层级：agent 按顺序做什么。每个步骤都以一个 **完成标准** 结束，也就是告诉 agent 工作已经完成的条件。让它_可检查_（agent 能判断完成和未完成吗？），并在重要处让它_穷尽_（“每个修改过的模型都已说明”，而不是“产出一个变更列表”）。含糊的标准会招来 **过早完成**。
2. **skill 内参考资料**：`SKILL.md` 中的定义、规则或事实，按需查阅。它常常是合法的扁平同级集合（比如评审的每条规则都在同一层级）这安排没问题，不是异味。_本 skill 全是参考资料。_
3. **外部参考资料**：从 `SKILL.md` 推到单独文件中的参考资料，通过 **上下文指针** 触达，只在指针触发时加载。（它覆盖了_披露型_参考资料，也就是像 `GLOSSARY.md` 这样的同级文件，仍然属于 skill；也覆盖完全的 **外部参考资料**，也就是存在于 skill 系统之外、任何 skill 都可以指向的材料。）

要求高的完成标准会推动彻底的 **幕后工夫**，也就是 agent 在工作内部做的挖掘；无论 skill 有没有步骤都是如此，因为“每条规则都已应用”对扁平参考资料的约束，就像“每个步骤都已完成”对序列的约束一样。

下推太少，顶部就膨胀；下推太多，又会藏起 agent 实际需要的材料。这个张力就是整个决策。

**渐进披露** 是沿梯子下移的动作，也就是从 `SKILL.md` 移到链接文件中，让顶部保持清晰。机制：skill 文件夹内的一个链接 `.md` 文件，以其内容命名（本 skill 把完整定义披露到 `GLOSSARY.md`）。有些 skill 会以多种方式使用，每种不同方式都是一个 **分支**，也就是不同运行会沿着 skill 走不同路径。分支是最干净的披露测试：每个分支都需要的内容内联，只被部分分支触达的内容放到指针后面。决定 agent 何时以及多可靠地触达材料的，是 **上下文指针** 的_措辞_，不是它的目标。

梯子决定一块内容_放多深_，**共址** 决定内容到了那里之后_和什么放在一起_：把一个概念的定义、规则和注意事项放在同一个标题下，而不是散落各处，这样读到一部分时，它的邻近内容也会一起进入视野。

## 何时拆分

**粒度** 是你把 skill 切得多细。每一刀都会消耗两种负载之一，所以只有当切分值得时才拆。两种切法：

- **按调用拆分**：当你有一个独立的 **主导词** 应该自行触发，或者另一个 skill 必须触达它时，拆出一个 **模型调用型** skill。你要为新的、总是加载的 **description** 支付 **上下文负载**，所以这种独立触达必须值得。
- **按序列拆分**：当一串 **步骤** 中后续的步骤（某个步骤的 **完成后步骤**）诱使 agent 匆忙跳过前面的步骤（**过早完成**）时，拆分这串步骤。让后续内容不在视野中，会鼓励 agent 在当前任务上做更多 **幕后工夫**。

## 修剪

让每个含义都有一个 **单一事实来源**：一个权威位置，这样改变行为只需要改一处。

检查每一行的 **相关性**：它是否仍然影响这个 skill 要做的事？

然后逐句搜捕 **空操作**，不是只逐行检查：把每个句子单独拿出来做空操作测试，一旦某句失败，就删除整句，而不是修剪其中几个词。要果断，失败的大多数 prose 都应该删掉，而不是重写。

## 主导词

**主导词** 是一个紧凑概念，已经存在于模型预训练中，agent 在运行 skill 时会用它思考（例如 _lesson_、_fog of war_、_tracer bullets_）。它在全文中反复出现（虽然不一定必须反复；强主导词可能只需要一次），积累出分布式定义，并用最少 token 锚定一整片行为区域，因为它招募了模型已经拥有的先验。

它以两种方式服务于可预测性。在正文中，它锚定_执行_：每次这个词出现，agent 都会伸手去拿同一种行为。在 description 中，它锚定_调用_：当同一个词存在于你的 prompts、docs 和 code 中时，agent 会把这种共享语言连接到 skill，并更可靠地触发它。

寻找把 skill 重构为使用主导词的机会。一个三元组在三个地方展开（**重复**），一个 description 花一句话去指向一个想法，都是在请求被 **折叠** 成一个 token。示例：

- “fast, deterministic, low-overhead” -> _tight_：一个阶段中反复陈述的同一种品质，折成一个预训练词（一个 _tight_ loop）。
- “a loop you believe in” -> _red_：把模糊闸门转成二元可观察状态（这个循环要么在 bug 上变 _red_，要么没有）。

你会赢两次：token 更少，agent 也有更锋利的钩子来挂住思考。假设每个 skill 都背着可以由主导词退役的复述，然后去找出它们。

## 失效模式

用这些诊断用户可能在 skill 上遇到的问题。

- **过早完成**：在步骤真正完成前就结束，注意力滑向_已经完成_。防御顺序：先锐化完成标准（便宜、本地）；只有当它不可避免地含糊，且你观察到匆忙行为时，才通过拆分隐藏完成后步骤（序列切分）。
- **重复**：同一个含义出现在多个地方。它增加维护和 token 成本，还会把某个含义在梯子上的显著性膨胀到超过真实级别。
- **沉积**：因为添加让人觉得安全、删除让人觉得冒险，于是陈旧层层堆住。任何没有修剪纪律的 skill 默认都会走向这里。
- **蔓延**：skill 只是太长，即使每一行都鲜活且唯一。它损害可读性和可维护性，并浪费 token。解法是梯子：把 **参考资料** 披露到指针后面，并按 **分支** 或序列拆分，让每条路径只携带所需内容。
- **空操作**：模型默认就已经会遵守的行，所以你付了负载却什么也没说。测试：它相较默认行为是否改变了行为？弱主导词（比如 agent 已经算是会彻底时还写 _be thorough_）就是空操作；修复方式是更强的词（_relentless_），而不是换一种技巧。
- **否定**：用禁止来引导会适得其反：_don't think of an elephant_ 点名了大象，让它更容易出现，而不是更少出现。提示 **正向目标**：陈述目标行为，让被禁止的行为根本不被说出口；只有作为无法正向表达的硬护栏时才保留禁止，并且即便如此，也要配上应该做什么。
